# Developer checks

Install Python development dependencies with `uv sync --locked` and JavaScript
checks with `bun install --frozen-lockfile`. All direct developer tool versions
are pinned in `pyproject.toml` and root `package.json`; their transitive versions
are recorded in `uv.lock` and `bun.lock`. Backend dependencies remain independent.

Run from the repository root without `PYTHONPATH=tools` or `MYPYPATH` overrides:

```sh
uv run --locked mypy
uv run --locked ruff check .
uv run --locked ruff format --check .
bun run typecheck
bun run check
uv run --locked pre-commit run --all-files
uv run --locked pytest tests/unit -q
```

Mypy is the single Python type checker. Its strict scope covers production Python
under `tools/`, `runtimes/`, `database/`, and `examples/`, including executable
Python templates. Namespace packages and explicit repository-root package bases
identify tooling as `tools.bench.*` exactly once. The compatibility CLI still
supports `PYTHONPATH=tools uv run python -m bench.cli`; that alternate import base
is for runtime compatibility tests, not a second Mypy source tree. Tests receive
Ruff lint/format and behavior regression coverage; they are not strict Mypy inputs.
PyYAML and boto3 CloudWatch/RDS stubs supply third-party signatures without
suppressing import or first-party typing errors.

Ruff owns Python in those four production directories and `tests/`, plus its
`pyproject.toml` configuration. Its include allowlist applies to root discovery;
force-exclude protects backend and generated artifact directories even when
paths are passed explicitly. Biome owns supported JavaScript under
`benchmarks/k6/`, `tools/`, and `examples/`; editable JSON templates/examples,
root tool configs and direct benchmark config examples are also included.
TypeScript checks the same JavaScript directories using `allowJs`, `checkJs`,
`strict`, and `noEmit`, with k6 declarations. JSDoc supplies types while scripts
remain executable JavaScript. Biome linting does not replace type checking.

Neither formatter includes `backends/`, historical results/reports, runtime JSON
locks/source proofs, generated artifacts, or dependency locks. New executable
source belongs in the explicit configured directories; extend the allowlists
when adding a new source directory. Validate protected hashes separately after
changes. Application and backend lockfiles must not be regenerated by root tools.

All gates are enforced locally and by `.github/workflows/quality.yml`. The CI
job installs locked dependencies, runs every pre-commit gate, then unit tests.
Actions are pinned by commit and uv/Bun by version. The quality job needs no cloud
credentials and does not start Docker workloads. Full production type hooks and
formatter hooks always run with `pass_filenames: false`; JSON/YAML syntax hooks
use explicit editable-source file predicates. Hooks only check; run `uv run
--locked ruff format .` and `bun run format` to apply formatting.

After installing dependencies and passing the checks above, inspect
`git config --get core.hooksPath` and any existing `.git/hooks/pre-commit`, then
install with `uv run --locked pre-commit install`. Preserve existing hooks;
pre-commit's migration mode chains an existing hook. Do not bypass hooks.

`benchmarks/k6/engine/contracts.d.ts` defines resolved stages, metric fields and
the synchronous generic `WorkloadContext.operation` contract. JSDoc imports are
only for static analysis. The engine wrapper has a declaration for its generated
workload import; trial preparation still replaces the JavaScript import with the
actual user entry. Input JSON is validated at runtime before it becomes typed
records. Actor fixtures remain inside SharedArray callbacks.

Wheels include these declarations and the Python `py.typed` marker. `bench init`
copies the full canonical contract alongside generated journeys; their JSDoc
imports resolve outside the checkout. Type checking a generated journey requires
TypeScript and `@types/k6`, but running it only requires k6. The engine runs with
k6 1.4.2; the pinned typings describe its used synchronous API surface.

Docker acceptance is opt-in and uses disposable local resources:

```sh
BENCH_INTEGRATION=1 uv run --locked pytest tests/integration/test_engine_k6.py -q
```

Broader Docker/SSH/queue acceptance commands and requirements are documented in
[reusable-engine verification](verification/reusable-engine.md).
